# FreshEye 运行时修复与双语体验升级设计

## 目标

在保留现有 Vue 3 + Vite + FastAPI 接口和 HTML 版本全部核心能力的前提下，修复当前线上阻断性问题，并完成无哈希多页面导航、双语 UI、响应式布局和 PDF 报告的整体收口。最终用户可以直接访问 `/`、`/guide.html`、`/fish.html`、`/about.html`，上传或选择样例图片完成识别，并在中英文界面中导出对应语言的完整报告。

## 已确认的根因

1. 路由使用 `createWebHashHistory()`，导航链接因此生成 `#/`、`#/guide` 等地址；这也让首页中的普通锚点和路由状态互相干扰。
2. `HomeView.vue` 将预览 `data:` URL 再交给 `fetch()` 转回文件。页面 CSP 的 `connect-src` 不允许 `data:`，浏览器拒绝请求后被统一显示为“网络错误”。后端健康检查和真实 multipart API 请求均正常，因此修复点在前端上传转换链路。
3. 选择样例只填充了预览，但上传区和样例区仍然同时显示，用户会看到第二个识别工作区；旧 HTML 版本在进入预览态时会隐藏入口区。
4. `frontend-dist/` 是 Vite 生成的部署产物，不是源码；源码和 GitHub Pages workflow 应保留构建配置，但本地生成目录不应作为源代码提交。
5. 模型文件名和文档/契约测试仍使用旧名字；测试样例已经由用户删除，仓库测试和文档不得继续把它当作开源目录。

## 架构方案

### 路由与部署

- 使用 `createWebHistory('/')`，让 Vue 负责页面内部状态，但使用 Vite 的静态入口 `index.html`、`guide.html`、`fish.html`、`about.html` 和 `404.html` 作为可直接访问的页面。
- 路由主路径统一为 `/`、`/guide.html`、`/fish.html`、`/about.html`、`/404.html`；旧的无扩展路径可保留为重定向兼容入口，但导航和文档只使用正式 `.html` 地址。
- 共享页面组件直接预加载，避免点击导航后因懒加载产生空白或明显等待；路由转场保持短促，并遵守 `prefers-reduced-motion`。
- 首页内部滚动使用 `scrollIntoView` 或普通 fragment，不再让首页 CTA 改写 Vue 路由；页面切换不会再出现 `#/`。
- `frontend-dist/` 继续作为 workflow 的构建输出目录并加入忽略规则；验证完成后删除本地目录，不删除 Vite 输出配置。

### 识别数据流

- 原始 `File` 直接提交给 API；只有图片经过压缩时才把本地 `data:` URL 用 `atob`/`Uint8Array` 转换为内存中的 `Blob`，禁止 `fetch(data:)`。
- 保留接口路径、multipart 字段和 `model_version` 参数不变；API 错误、超时、低置信度和服务不可用分别映射到已有的双语提示。
- 样例加载沿用静态资源，但等待 `handleFile()` 完成、按钮显示忙碌态并锁定重复点击；进入预览态后只保留一个检测工作区，清除/重新选择后恢复入口区。

### 双语与 UI

- 所有用户可见文案、状态、弹窗、历史记录操作、结果标签、报告字段和打印控制都从统一 i18n 读取；修正文案中中英混写和英文不自然表达。
- 右上角使用紧凑的分段式语言开关：当前语言为填充胶囊，另一语言为低强调文本；按钮具备 `aria-pressed`、键盘焦点和移动端足够点击尺寸。
- 保留 FreshEye 的深海蓝/青绿色视觉识别，统一卡片半径、阴影、间距和按钮状态；错误、成功、警告颜色满足对比度要求。
- 桌面端维持双栏信息层级和宽屏留白；移动端将导航、上传操作、结果卡片、对比滑块、历史记录和报告按钮变为单列/可滚动布局，避免横向溢出。
- 页面首次引导不能长期拦截导航；关闭状态持久化，键盘可操作，必要时允许用户重新打开。

### PDF 报告

- 报告继续由 `pdfReport.ts` 生成独立打印窗口，使用当前 locale 的标题、结果、置信度、视觉解释、建议和页脚。
- 中英文都要验证原图、Grad-CAM 图、模型名称、日期格式、打印/保存 PDF、下载 HTML、关闭窗口等功能；报告中的按钮不应进入正文打印区域。
- 报告生成不依赖站外字体或 API 请求，图片使用已有 data URL，确保离线打印窗口仍可完整呈现。

## 验收矩阵

| 项目 | 验收标准 |
| --- | --- |
| 模型改名 | `models/fishfreshnetv2.pth` 存在，旧文件名及文本引用清理，HF Space 独立部署权重不被误改。 |
| 测试目录 | `test-samples` 和 `test_examples` 不在工作树/发布清单中，契约测试不再要求样例目录。 |
| 构建产物 | 本地 `frontend-dist` 可由构建生成、被忽略，最终源代码提交不含该目录；Pages workflow 仍可构建并发布。 |
| 页面显示 | 四个正式入口和 404 页面直达后均有标题与正文，不依赖旧 hash 状态。 |
| 识别 | 真实上传和内置样例均能发出 multipart 请求并显示结果，不出现 CSP/data URL 网络错误。 |
| 工作区 | 样例选择不会导航或创建第二个识别框；预览态入口区隐藏，清除后恢复。 |
| 导航 | 页面链接切换无 hash、无空白、无明显延迟；移动菜单可开关且不锁死页面滚动。 |
| 双语 | 中英文切换覆盖所有页面、状态、弹窗、历史与报告；英文无遗留的用户可见中文。 |
| 交互 | 拖放、粘贴、相机、模型选择、低置信度处理、结果 tabs、Grad-CAM、历史收藏均保持可用。 |
| 响应式 | 1440px 桌面和 390px 手机视口无横向溢出，关键按钮、文本和图片可用。 |
| PDF | 中英文各生成一次报告，预览内容和打印/保存控件完整，图片与字段无缺失。 |
| 后端 | FastAPI 测试通过，health 与真实 v2 请求成功，CORS 允许正式站点。 |

## 验证策略

先为路由、上传转换、资源清理、样例预览态和文案建立会失败的契约测试，再实现修复。随后执行 TypeScript 检查、Node 契约测试、Vite 生产构建、FastAPI 测试、差异/引用扫描，并使用浏览器对正式入口、真实 API 上传、样例、双语、PDF 和桌面/移动端进行多轮 smoke test。只有所有验收项通过后，才直接提交并推送 `main`。
